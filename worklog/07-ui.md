# Worklog 07 - The static research site

**Stage:** UI only. `uv run vc-scout build-ui --run-id <run-id>`
**Scope as given:** a read-only static site generated from validated artifacts - a
portfolio page and one page per company - with search, filters and sorting in vanilla
JavaScript. Explicitly excluded: React, Next.js, an API server, a database,
authentication, any frontend build tool, any CDN, and any external runtime dependency.

## What was built

- `src/vc_scout/render/html.py` - the site's own Jinja environment (autoescape on), the URL
  and JSON escaping primitives, and the view models for both page types.
- `src/vc_scout/templates/site/_base.html.j2`, `index.html.j2`, `company.html.j2`.
- `src/vc_scout/templates/site/assets/styles.css`, `app.js` - copied verbatim beside the
  generated pages; they contain no run data.
- `src/vc_scout/stages/ui.py` - the stage: load, order, render, write assets, clean up.
- `src/vc_scout/models/report.py` - `UiReport`, `PageFailureRecord`.
- `src/vc_scout/cli.py` - `build-ui`, with `build-site` kept as a deprecated alias.

## Architecture

`stage → view model → template`, the same split the Markdown renderer uses. The stage reads
artifacts and decides nothing about presentation; the view model computes every displayed
value; the template places finished strings. Ordering is not reimplemented - the stage
imports `sort_key` from `render/ranking.py`, so the site and `ranking.md` cannot disagree
about which company is first, and a test asserts the rendered row order equals
`recommendation-report.json`'s `ordered_company_ids`.

The wording layer is shared too: `render/call.py` supplies the one-sentence call, the
"how to read this" line, the guardrail labels and the short rationale, so the memo and the
page say the same thing about the same company. What is *not* shared is escaping.

## Escaping runs the opposite way from the memo renderer

This is the thing most worth knowing before reading the code. The Markdown renderer escapes
in Python before a value reaches its template, and its environment has autoescape off.
The site does the reverse: autoescape on, view models carry raw text. Each format uses its
own correct escaper rather than a second invented one.

There is exactly one value in the site marked safe - the JSON block the filters read - and
the reason is that HTML escaping there would be actively wrong. A browser does not decode
entities inside a `<script>` element, so an autoescaped `&quot;` would corrupt the JSON
rather than protect it. The dedicated escape turns `<`, `>`, `&`, U+2028 and U+2029 into
unicode escapes, which is strictly stronger for that context; a test feeds a
`</script><script>alert(1)</script>` company name through it and asserts the block still
parses and contains no `<`.

## What was difficult, and what changed during implementation

**A CSP with no `unsafe-inline` outlaws the obvious way to draw a bar.** Score bars started
as `style="width:40%"`. That is an inline style, which `style-src 'self'` blocks, so the
bars would have rendered at zero width on any browser enforcing the policy - and the failure
is silent. Widths are now CSS classes in 5% steps (`bar__w40`), generated once in the
stylesheet. The same constraint is why there is not a single `style=` attribute in either
template, and a test asserts it.

**A bar that is an inline `<span>` has no height.** In the table the bar sits inside a flex
column, so `height: 6px` applied and it looked right. In the company page header it was a
bare inline span, `height` was ignored, and the fill inside it stretched to the line box -
a 6px bar rendered as a 100px vertical block. Only the browser screenshot caught it; the
HTML was valid and every test passed. `.bar` is now `display: block`.

**`frame-ancestors` cannot be delivered by a meta tag.** It was in the first CSP and every
page logged a console error for it. Removed, with a comment saying why, rather than left in
as decoration that looks like protection.

**Table layout needed fixing, literally.** Percentage column widths are hints that automatic
table layout ignores when content forces widths, so the product column - the one a partner
actually reads - stayed pinched while short labels took the space. `table-layout: fixed`
above 860px, with explicit percentages, plus `overflow-wrap: normal` on headers after
"CONFIDENCE" wrapped as "CONFI / DENC / E".

**The mobile caption collapsed.** With `table { display: block }` for the card layout, a
`display: table-caption` box sizes to the widest cell and wrapped the caption sentence into
a column two words wide. `caption { display: block }` inside the mobile query.

**The memo link was one directory level short.** `../memos/<id>.md` from `site/companies/`
resolves to `site/memos/`, not to the run root. The link-resolution test caught it, which is
the argument for asserting that every internal link exists on disk rather than that it looks
right.

## Trade-offs and remaining limitations

- **No visual regression testing.** The screenshots taken during this stage are evidence for
  this build, not a check that survives into CI. The bar-height defect above is exactly what
  a rendered-output test would catch and what the current suite cannot.
- **Filtering is limited to hide-and-reorder.** No paging, no highlighting, no server-side
  search. At fifteen candidates that is the whole requirement; at several hundred rows the
  page would need something else.
- **Two escaping regimes to keep straight.** Documented at the top of both renderers, and the
  shared pieces are imported rather than copied, but it is a real thing to remember.
- **The stylesheet is hand-maintained** with no component model across the two templates.
  A third page type would be the point to reconsider.
- **A discovery-recorded title can still read oddly** on a company whose site could not be
  fetched - the same upstream sourcing quirk noted in worklog 06. The site shows what an
  artifact recorded and does not second-guess it.
- **`--force` replaces only what the generator owns** (`index.html`, `ui-report.json`,
  `companies/`, `assets/`). A file a human left in `site/` survives, deliberately - a build
  that deletes what it did not write is a build that can lose work.

## Test coverage added

`tests/unit/test_ui_stage.py` (42) plus 6 CLI tests. Covered: all 15 company pages and the
index render; byte-identical rebuild; no build timestamp; report counts reconcile with
`recommendation-report.json`; page order matches the Markdown ranking; every internal link
resolves on disk (91 of them in the live build); back, previous, next and memo links on
every company page; seven scorecard dimensions and a total; exactly the validated 2-3
changers; guardrails and the model/policy disagreement visible; identity and analysis
warnings labelled separately; the zero-claim watch reading as missing evidence; the
no-meeting explanation reconciling with the report's own counts; hostile HTML escaped, not
executed; a `</script>` payload unable to break the embedded data; every non-http URL scheme
refused; a CSP on every page with no `unsafe-inline`; no external CSS, JS, font or image; no
inline handler or inline style; the script free of markup-assigning properties and network
calls; heading hierarchy; labelled controls and scoped table headers; the call never carried
by colour alone; stale page cleanup; `--force` preserving what it does not own; the
overwrite guard; and that building needs no network and no credential.

## Polish pass, driven by the desktop screenshots

The first build was professional but wrong for the job. Reading the 1440x900 screenshot
rather than the HTML made three things obvious that no test had failed on.

**The pipeline was below the fold.** The thesis panel and the no-meeting explanation - both
reference material - sat between the run summary and the table, so the first candidate
began at roughly 1,230px on a 900px viewport. A partner opening this to triage had to
scroll past the firm's own thesis to reach the work. Both are now native `<details>`
disclosures at the foot of the page, collapsed, keyboard accessible and working with
JavaScript off. The first row now starts at **412px**, and five rows are visible in the
first viewport.

**Rows were memo-length.** Each row carried the full plain-language product paragraph, so a
row ran 200-300px and the table read like fifteen short memos. Product is clamped to two
lines and buyer and workflow to one each, with a `max-height` fallback for browsers without
`-webkit-line-clamp`. Rows are now a uniform **112px**; the full text is one click away.

**A bare "Watch" badge was ambiguous.** All four watches in this run are evidence-shortfall
guardrails, and the badge did not say so - a reader could not tell "promising but unproven"
from "we found nothing about this company". Watches now carry a qualifier drawn from the
guardrail that fired (`no usable evidence`, `needs research`), an evidence-backed thesis
mismatch pass is marked `outside thesis`, the flag chips name the actual guardrail reason
instead of the word "Guardrail", and "Model differs" became "Policy override". These are
display labels only: the persisted decision, the guardrail list and the report counts are
untouched, and a test asserts it.

Also from the screenshots: the confidence cell read `1 / 10 / 4` with a legend underneath,
which made a reader decode before they could read - it is now three labelled values;
"Ranking (Markdown)" became "Export ranking"; the filters collapsed from a wrapping grid
with a full-width reset into one row with a small secondary reset at the end; and Max
achievable and Flags merged into one secondary "Context" column so the five columns that
carry the decision keep the width.

Row interaction stayed deliberately conventional: the company name is the primary link and
a small "View analysis" link sits beside it. Making the whole row a click target would have
broken table semantics and fought the external website link inside it.

**What the screenshots caught that the tests could not.** Everything above. The suite
asserted structure, links, escaping and determinism - all of which passed on a page that
was hard to use. That gap is the honest argument for looking at rendered output, and it is
still unautomated.
